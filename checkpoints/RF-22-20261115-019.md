# RF-22 nested-workflow checkpoint

- Normal development now uses a host-native baseline with Reverse/REA/Spec/
  Builder capabilities enabled on demand.
- A main project can create isolated analysis or reconstruction subcases during
  development. Each subcase owns its target, route, Evidence, tasks and
  candidate; only reviewed Evidence-backed conclusions return to the main
  project.
- This covers mixed workflows such as developing a website while researching a
  reference website, or building an application while analyzing a related APK
  or desktop program.
- Existing RF-17 through RF-22 target-chain Evidence and provider boundaries are
  unchanged. Tests, contracts and handoff checks remain passing.
