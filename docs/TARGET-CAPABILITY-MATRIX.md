# Target capability matrix

Reverse Fusion does not need to execute every future target in advance. It
defines the route, evidence contract and variant-handling path for each target
family; representative fixtures validate that the shared pipeline is wired
correctly. New packers, obfuscators, runtimes and providers enter as target
cases or small capability updates.

| Family | Static route | Dynamic route | Current state | First real target gate |
|---|---|---|---|---|
| WASM | WABT `inspect_wasm_artifact`, interface comparison | WABT interpreter fixture only | verified for bounded fixture; ledger ready | retain original/candidate Evidence and runtime value comparison |
| JavaScript/Web | REA `analyze_javascript_application`, export-shape comparison | finite Node module replay | reviewed answer export pass/ledger ready; complete graph unknown with 4 required open obligations | add package/parser evidence or browser/CDP authority when the target requires it |
| Electron | REA Electron page/scenario tools | owned Electron scenario | contract planned | one local Electron fixture |
| PE/.NET | REA managed artifact/member inspection and exact comparison | .NET 8 command-line replay | verified for bounded managed method; ledger ready | extend with native/obfuscation probes when supplied |
| APK/DEX | REA Android package/class inspection through pinned JADX headless MCP | adb/emulator/Frida provider-dependent | build and manifest/member projections pass/static ledger ready; method-body equivalence and Android runtime unknown | real Activity/behavior/device case required before a launch/runtime equivalence claim |
| Native ELF/PE | native layout/hardening/disassembly tools | PTY/debug provider-dependent | Windows PTY unsupported currently | Linux/macOS provider or qualified Windows cleanup provider |
| Protocol/API | packet/HAR/static contract tools | capture/replay provider-dependent | contract planned | one local fixture capture |

The matrix is a routing and contract inventory. A target-level claim still
requires the Evidence and comparison for that target.

RF-25 representative source candidates are generated by the host agent in the
current conversation. Its session file-boundary checks and independent business
observations are separate. Optional child CLI credits/login failure is not a
requirement to change the active host's model or account. Current archive IDs
and file hashes are indexed by `evidence/rf22/manifest.json`.

RF-24's preservation remains in the RF-25 inventory: enhanced Reverse hard-target methods and helpers, including
packing/unpacking, anti-analysis, OLLVM, .NET obfuscation, Android dynamic DEX/JNI
and JS/WASM context. Routes expose their required reads and fail when required
support is missing. Content preservation and decision-contract tests do not
qualify every protector or dynamic provider; see `REVERSE-CAPABILITY-AUDIT.md`.
