# 不懂技术，也可以这样用

部署完成后，在 Codex 打开你这次项目的文件夹，把待分析的文件放进去，直接用平常
说话的方式说明目标。共享工具仓库保留在安装位置，分析记录和成果放在当前项目。
不用把整套工具复制到每个新文件夹，也不用背任何组件名称或命令。
当前完整工程版是1.1.0，面向Windows x64和Codex。安装或交付这套工具不需要你
额外提供测试软件；你以后做某个具体项目时，智能体才按那个项目的实际需要请求帮助。

## 第一次安装或换电脑

把这个仓库链接发给当前智能体，说：

> 帮我把这个项目安装到当前电脑，主要在 Codex 里用。请实际装好它需要的组件，检查能不能用，并告诉我安装结果。
>
> https://github.com/gthubtom1/reverse-fusion

智能体负责读取仓库的安装入口、准备运行环境并检查真实组件。安装遇到问题应说明
具体原因并修复或请求必要帮助。看到“核心组件未安装”就还没有完成安装。
当前发布实测为 Windows x64 + Codex；其他系统或宿主要报告各自实际验证的情况。

## 开始一个新项目

例如你想分析并复刻一个桌面程序，在 Codex 打开存放该程序的新项目文件夹后说：

> 帮我分析这个软件，然后复刻出一个界面和功能都一样、能实际使用的版本。我不懂技术，需要我提供什么就直接告诉我。

只想先弄清原理，可以说：

> 帮我看懂这个程序主要做什么、怎么工作的，先分析，暂时不要写复刻版。

研究网站时，提供网址或已保存的页面材料并说明你想弄清的部分：

> 帮我分析这个网站的页面和功能，我想做出一样的使用效果。需要登录或我手动操作时告诉我。

研究 APK、协议、算法或做其他专门分析，同样说明材料在哪里、你想得到什么结果。
例如“帮我看这个 APK 的数据怎么处理”“帮我分析这份抓包里客户端和服务器怎么交互”。
你不必知道它用什么语言、有没有壳，智能体负责先判断，再根据发现调整方法。

## 过程里怎样继续说

| 你当前的情况 | 可以直接这样说 |
|---|---|
| 想继续上次工作 | 继续刚才那个项目，接着没完成的地方做。 |
| 想了解进度 | 现在已经确定了什么？还缺什么？先用我能懂的话说。 |
| 觉得效果有差异 | 这里和原版不一样：我点这个按钮后，原版会……，现在却……。 |
| 能提供操作帮助 | 我可以操作原软件，你告诉我需要点哪里、记录什么。 |
| 某个功能很重要 | 这个功能必须保留：……，不能只做页面。 |
| 想暂停 | 先暂停，把当前进度和下次从哪里继续保存好。 |
| 补充新要求 | 这是补充之前的要求：……，原来的目标继续保留。 |

发现差异时，操作步骤、输入示例、截图/录屏或错误提示都很有帮助，不需要换成技术术语。
账户、测试资料或运行环境需要你协助时，智能体应解释用途，并只请求当前必要的内容。

## 正常工作应该是什么样

智能体先识别材料、调查功能与依赖，说明已确认的事实和缺失的信息。材料足够后，
再安排实现、运行、与原版比较和修正。它可以先做小部分核实路线，但应一直保留你要
整个产品的目标，不能把一个演示页面或局部结果直接说成整软件完成。

你无需在每个阶段发一段专业提示词。“继续”足够接续已有工作；如果你需要作出决定，
智能体应使用具体的产品或操作问题向你解释。遇到困难时应给出已尝试方法和下一步，
不能反复空转，也不能用“已安装”“看起来相似”代替实际功能验证。
某个功能还需要你提供信息时，智能体应继续其他不受影响的工作；你不必负责催它选择
下一工具或设计专业路线。案例可以分多次完成，你的完整目标应一直保留。
