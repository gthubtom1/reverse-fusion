# Acceptance Matrix

RF-01 static contracts: JSON parses, versions fixed, unknown fields rejected, profiles match, official/source manifests agree, path and hash boundaries are checked.

RF-02 route/case: dry-run route, no duplicate route owner, case pointer, decision delta and carry-forward references.

RF-03 REA: typed Evidence/bundle/unknown/comparison wrappers; real MCP handshake remains host-dependent.

RF-04 vertical slice: console correct pass, wrong fail, missing evidence unknown (automated).

RF-05 Craft: fixed source/patch identity, exact six-tool gate, baseline/path/task/model drift rejection, typed report and cleanup; current installed companion remains unsupported until R46 qualification.

RF-06 Spec: official 1.4.0 CLI check/init, project-local source refs, feature artifacts and append-only converge.

RF-07 acceptance: spec compliance, behavior equivalence and independent runtime acceptance separated; deterministic fixture pass/fail/unknown recorded.

RF-08 hosts: Codex/Pi/Claude discovery and read-only plan; host loading remains a separate handshake.

RF-09 hard-target: provider capability and cleanup gates recorded; no real target claim from the console fixture.

RF-10 release: clean tree, tests, checkpoint, rollback and upstream maintenance records, GitHub push.

RF-11 REA/WABT: pinned WABT archive and executable hashes, process-local REA doctor, complete WASM Evidence ID, artifact digest and explicit runtime/network limitations.

RF-12 vertical chain: original/candidate REA Evidence, interface comparison, runtime fixture result, correct candidate pass, wrong candidate fail and missing candidate unknown.

RF-13 Craft fallback: local candidate writer passes capability, baseline, task digest, single-writer and cleanup gates; it is clearly distinguished from a model-based Craft backend.

RF-14 obligation closure: the bounded WABT runner emits authenticated
`rea.reconstruction-proof` Evidence, the canonical bundle retains source and
comparison links, and the official REA ledger reports `ready` with
`required_open: 0`.

RF-15 release gate: the GitHub fresh clone passes install preview, contracts,
plan, doctor and handoff from the remote `master` branch.

RF-16 host/provider probes: Codex and Pi fixed-sentinel handshakes pass;
Claude startup reaches a typed missing-login boundary; Craft Codex agent-cli
`ai test` and clean-room chat pass while native R46 qualification remains a
separate gate.

RF-17 portable Reverse: local route manifest and descriptors resolve from a
fresh clone without the old receipt; external route remains explicit and
read-only.

RF-18 host Builder: Codex writes a bounded candidate and completes
prepare/build/check/refine/return_summary/cleanup without model selection or
global configuration mutation.

RF-19 Web, RF-20 PE/.NET and RF-21 APK/DEX: each has original/candidate REA
Evidence, frozen Spec tasks, build/run observation, comparison, canonical proof,
cleanup and a target ledger. Web package/parser and APK device runtime gaps are
retained as unknown.

RF-22 product acceptance: all `docs/PRODUCT-GOAL.md` gates are directly
evidenced; the repository is tagged `reconstruction-product-v1-final`. The
completion rule validates product logic and representative contracts, without
requiring exhaustive execution of every future target variant.
